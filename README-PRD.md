> 最后更新：2026-11-18
> 关联文档：README-PTD.md（项目技术文档）、README-BTD.md（后台服务技术文档）
> 适用读者：产品、开发、测试、AI 编码助手

## 1. 背景与目标

为单人/少人服务型商户（美容、美甲、美发、宠物美容、私教、家政等）提供一套「预约 + 定金 + 排班」的轻量 SaaS 系统，解决线下口头预约带来的错峰、超卖、爽约与定金纠纷问题。

目标：用最小可行产品（MVP）跑通核心闭环，做到可演示、可复制的单租户形态，数据模型预留多租户扩展能力。

## 2. 术语表

| 术语 | 说明 |
|---|---|
| 服务项目 | 商户可提供的服务（如「小气泡清洁」），含默认时长、价格、定金 |
| 资源 | 可被预约的人力/物理资源，分两类：技师（STAFF）、床位/房间（ROOM） |
| 排班 | 商户为某资源在某日期设置的可售时间段（窗口） |
| 时段库存 | 由排班生成的可售时段单元，含总容量与已占用数 |
| 预约单 | 顾客对某服务 + 某时段的一次预约记录 |
| 定金 | 预约时需支付的锁定金额，单位为「分」 |
| 核销 | 顾客到店后商户确认服务完成，预约单置为已完成 |

| 功能 | 顾客 | 商户员工 | 商户管理员 |
|---|---|---|---|
| 浏览服务项目 / 可售时段 | ✅ | ✅ | ✅ |
| 创建预约 + 支付定金 | ✅ | — | ✅ |
| 取消预约 / 申请退款 | ✅ | — | ✅ |
| 管理服务项目 | — | — | ✅ |
| 管理资源与排班 | — | ✅ | ✅ |
| 查看日历 / 预约列表 | — | ✅ | ✅ |
| 手动锁定 / 释放时段 | — | ✅ | ✅ |
| 发起核销 | — | ✅ | ✅ |

角色说明：

- 顾客：通过小程序/移动 H5 自助预约与支付。
- 商户员工：使用后台处理排班与核销，无权修改服务项目与价格。
- 商户管理员：拥有商户侧全部权限，管理服务、价格、员工账号。

## 4. 功能范围（第一期）

### 4.1 核心闭环（必须）

1. 顾客选服务（含默认时长） → 选日期时段 → 付定金 → 锁定预约。
2. 商户设服务/排班 → 看日历 → 核销。
3. 顾客取消 → 按规则退定金/释放时段。
4. 超时未支付 → 自动释放时段。
5. 商户手动锁定/释放时段。

### 4.2 功能模块清单

| 模块 | 顾客端 | 商户后台 |
|---|---|---|
| 服务管理 | 浏览 | 增删改查、上下架 |
| 资源管理 | — | 技师/床位增删改查 |
| 排班管理 | — | 按资源按日设置可售窗口 |
| 时段与库存 | 查看可售时段与余量 | 日历视图、手动锁定/释放 |
| 预约 | 创建、支付、取消 | 列表查看、核销、取消 |
| 定金流水 | 我的订单/退款 | 流水查询 |
| 账号 | 登录（手机号） | 员工登录、角色管理 |

## 5. 核心业务流程

### 5.1 预约流程

1. 顾客选择服务项目 → 系统展示该服务默认时长下的可售时段（含余量）。
2. 顾客选择时段 → 提交预约 → 系统创建预约单（状态：待支付）并「预占」时段。
3. 顾客支付定金 → 支付平台异步回调 → 系统确认预约（状态：已确认）。
4. 若顾客在支付时限内未支付 → 定时任务释放预占时段，预约单置为「已过期」。

### 5.2 取消与退款流程

1. 顾客在「我的预约」发起取消。
2. 系统判断距离服务开始时间：
   - ≥ 24 小时：允许自助取消，自动发起全额退定金，释放时段。
   - < 24 小时：不允许自助取消，提示联系商户走售后。
3. 商户后台也可取消预约，取消后释放时段并按规则退款。

### 5.3 核销流程

1. 顾客到店，商户在后台找到对应预约单发起核销。
2. 顾客确认（或商户代确认）。
3. 预约单置为「已完成」，定金归入商户结算（演示环境仅记录状态）。

### 5.4 排班与库存生成流程

1. 商户为资源设置某日期、某时段的可售窗口（排班）。
2. 系统按排班窗口 + 服务时长拆分生成时段库存（如 9:00–12:00、120 分钟服务 → 2 个槽位）。
3. 商户可对单个时段手动锁定（暂停售卖）或释放。

## 6. 业务规则

| 规则 | 取值/判定 |
|---|---|
| 时段占用判定 | 预约成功且定金支付成功；支付前仅「预占」 |
| 待支付占位时限 | 最长 2 小时，超时自动释放 |
| 预约提前量 | 仅可预约「服务开始 ≥ 当前时间 + 24 小时」的时段 |
| 取消退款 | 服务前 ≥ 24 小时可全额退定金；< 24 小时不可自助取消 |
| 改约 | 第一期不支持，先取消再重新预约 |
| 核销 | 门店后台发起，客户确认 |
| 金额精度 | 一律以「分」为整数存储，禁止浮点计算 |
| 时区 | 统一 Asia/Shanghai |

## 7. 范围外（第一期不做）

会员体系、优惠券/满减、多门店结算、营销裂变、评价体系、消息推送模板、多租户计费与配额、技师端独立 App、语音/视频咨询。

## 8. 验收标准

1. **并发抢最后时段**：同一时段仅剩 1 个库存，≥ 10 个请求同时下单，只有 1 个成功占用，其余均返回「时段已满」且不产生脏数据。
2. **支付回调幂等**：同一笔支付回调重复推送 N 次，只产生 1 次「确认预约 + 扣减库存 + 入账」，结果一致。
3. **超时释放**：待支付预约超过 2 小时未支付，定时任务自动释放时段，预约单置为「已过期」。
4. **取消退款**：服务前 ≥ 24 小时取消，定金全额退回，时段立即释放可再次售卖。
5. **金额精度**：全链路金额以「分」为整数存储，任意操作后无浮点误差、无 0.01 元级偏差。

## 9. 非功能需求

- 界面：中文；顾客端移动优先，商户后台桌面日历优先。
- 多租户：演示为单租户，所有核心表预留 merchant_id。
- 时区：Asia/Shanghai。
- 性能（演示环境）：核心读接口 P95 < 500ms，写接口 P95 < 1s。
- 安全：密码加密存储、接口鉴权、商户数据隔离（防越权）。
- 可观测：关键操作（下单、核销、退款、锁定）写审计日志。
- 一致性：库存扣减、退款、释放均为数据库事务 + 原子条件更新。
